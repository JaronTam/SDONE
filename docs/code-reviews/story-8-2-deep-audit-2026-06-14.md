### 偏差-1: PATCH-1 修复不完整 — 选择变更路径遗漏

**偏差等级:** 🟡 P2（遗漏，非错误）

**此前表述（审查报告 PATCH-1 修复方案）:**
> 在 `handleMouseUp` 中，当 `onModuleSelect(null)` 被调用时，同步重置 `isEditingName`

**实际缺陷:**
修复仅在 `onModuleSelect(null)` 的两个调用点添加了 `resetSelectionState()`，但 `handleMouseUp` 中还有 `onModuleSelect(hitId)` 路径（点击不同模块切换选择），此路径未调用 `resetSelectionState()`。

**遗漏路径:**
```
1. 用户选中模块 A → isEditingName = false
2. 用户按 Enter → isEditingName = true
3. 用户点击模块 B → onModuleSelect('B') 触发
4. 但 isEditingName 仍为 true！
5. 用户按 Enter → !isEditingName 为 false → 不进入编辑模式
   → 但也不会放置模块（PATCH-5 修复后）
   → Enter 键被静默吞掉，无任何效果
```

**影响评估:**
- PATCH-5 修复后，此遗漏不会导致 `onModulePlaceAtCenter` 被错误调用
- 但会导致 Enter 键在切换选择后首次按下时无响应（静默失败）
- 用户体验：选中模块 B 后按 Enter 无反应，需按第二次才能进入编辑模式

**修正状态:** ✅ 已修正（PATCH-1a：在 `onModuleSelect(hitId)` 后也调用 `resetSelectionState()`）

## [修正与原点溯源]

### 偏差-1 原点溯源

**第一性原理:** 选择状态（selection）的语义包含两个互斥事件：
1. **取消选择**（deselect）：从有选择变为无选择
2. **选择变更**（reselect）：从选择 A 变为选择 B

两者都意味着"前一个选择上下文结束"，因此所有与前一个选择关联的临时状态（`isEditingName`、`hoveredDiamond` 等）都应被重置。

**偏离原因:** 审查时将 PATCH-1 的分析焦点放在"取消选择"路径上，因为这是最直观的遗漏点。在修复方案中，仅追踪了 `onModuleSelect(null)` 的调用点，未系统性地追踪所有 `onModuleSelect` 调用点。这是 **分析粒度不足** — 按回调调用分类而非按语义事件分类。

**认知偏差分析:** 模型在生成修复方案时，采用了"找到遗漏点 → 在遗漏点补代码"的局部修复策略，而非"枚举所有语义等价路径 → 统一修复"的系统性策略。这是典型的 **锚定偏差** — 被最初的"取消选择"分析锚定，未扩展到"选择变更"。

### 偏差-2 原点溯源

**第一性原理:** 代码修复的完整性要求修复实现 + 测试验证成对出现。没有测试的修复是脆弱的 — 它解决了当前问题但不防止回归。

**偏离原因:** 审查报告正确识别了缺失测试，但修复执行时优先级偏向"让测试通过"而非"补充测试覆盖"。这是 **完成偏差** — 在所有现有测试通过后，模型倾向于认为任务完成，而非继续补充缺失测试。
