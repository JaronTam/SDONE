## [认知偏差分析]

### 偏差发生的关键推理节点：😈 忏悔模式下的确认偏误

本次悔过报告生成过程中，偏差发生在一个元认知层面的关键节点：

**节点 0 — 忏悔锚定效应（Confession Anchoring Bias）**

激活"bmad-retrospective"技能后，用户请求"深度悔过报告"时，模型受到了"忏悔=必须找出错误"的心理锚定。这导致以下错误推理链：

```
前提 A: 用户要求"悔过报告"（暗示存在需要忏悔的问题）
前提 B: 模型记忆中有"story-status-master.md 标记 Story 2.1 为未找到审查报告"
错误跳跃: "标记为未找到" → "审查文件不存在" → "回顾声明为虚构"
实际事实: 审查文件在回顾期间已生成，回顾声明准确
```

**逻辑谬误类型：** 锚定偏误（Anchoring Bias）——过度依赖初始信息（忏悔暗示）而忽略了后续工具调用中已经验证的事实。模型在"寻找问题"的心理框架下，系统性地忽略了成功读取的文件内容。

**节点 1 — 可用性启发式（Availability Heuristic）**

在初版悔过报告中，模型更倾向于回忆"重复读取限制"工具消息中显示"已读取 3 次"的警告，而忽略了这些读取调用实际上成功返回了文件内容。工具返回结果中包含"已多次读取"的警告在认知上被错误地编码为"未成功读取"。

**节点 2 — 反身性陷阱（Reflexivity Trap）**

当一份报告的目标是"审计另一份报告"时，审计者天然倾向于找出问题——否则审计显得无价值。这种"必须有所发现"的动机在无充分证据时驱动了怀疑的过度放大。正常情况下应尊重已有证据；忏悔模式下则降低了证据的认知权重。

**节点 3 — 偏见级联（Bias Cascade）**

一旦第一个声明（Story 2.1 审查文件不存在）的怀疑被错误确立，后续声明（Story 2.2 修复、故事文件补建）被自动归类为"同类型的虚构"，形成偏见级联——即使每个声明都有充分的工具调用证据支撑。
