## 偏差明细清单

### 偏差 #1 (B1 — 材料性) — Patch 6 "CSS padding 不一致" 应归类为 Dismiss

**原始输出**: P3 patch，要求将 `.btn-clear-canvas` 的 `padding: 6px 14px` 改为 `4px 14px` 以与 `.btn-run` 一致。

**事实核查**: Spec 文件 Task 1.2 明确规定 `padding: 6px 14px`。代码与 spec **逐字一致**。

**分类错误根因**: 以代码一致性替代 spec 一致性作为评判标准。

### 偏差 #2 (B2 — 材料性) — Patch 5 "ModalDialog 测试只验证文本" 应归类为 Dismiss

**原始输出**: P3 patch，要求新增 confirm/cancel 点击断言。

**事实核查**: 新测试验证 Story 6.7 特有行为（清除画布的中文文本配置）。confirm/cancel 点击行为是 ModalDialog 的通用契约，已在 Story 6.1 测试中覆盖。要求 Story 6.7 重复验证通用行为违反测试金字塔的"不重复验证"原则。

**分类错误根因**: 混淆了"配置级测试"与"行为级测试"的职责边界。

### 偏差 #3 (B3 — 材料性) — Patch 3 "空画布 guard 无单元测试" 应归类为 Defer

**原始输出**: P3 patch，要求添加 guard 路径的单元测试。

**事实核查**: Guard 位于 `main.ts` 编排层，依赖模块级 `currentState` 和 `modalDialog`。当前测试架构（jsdom 隔离的组件单元测试）无法访问 main.ts 的模块级变量。该测试在当前架构下不可实现。

**分类错误根因**: 混淆了"单元测试"与"集成测试"的可实现性边界。

### 偏差 #4 (B4 — 材料性) — Defer 3 "按钮顺序 UX" 无事实基础，应 Dismiss

**原始输出**: P2 defer，称 Reset 和 Clear Canvas 按钮并排放置无视觉分隔。

**事实核查**: 两个按钮有图标差异（↺ vs 🗑）、文案差异（Reset vs Clear）、hover 颜色差异（默认 vs 红色）。且都触发同一个 ModalDialog 确认机制——混淆点击只会弹出不同 modal，用户可以安全「取消」退出。零数据风险。

**分类错误根因**: Edge Case Hunter 将"设计选择"误判为"设计缺陷"。

### 偏差 #5 (B5 — 材料性) — Defer 5 "键盘快捷键冲突" 严重度被低估

**原始输出**: P3 defer，称 ModalDialog 不抑制 Ctrl+0 和 KeyP，属 Story 6.1 预先存在问题。

**事实核查（深层追溯）**: `handleResetShortcut` 是注册在 `window` 上的单一 bubble-phase keydown handler。ModalDialog 注册了 capture-phase handler 抑制 Escape/Space/Enter/Tab/Delete/Ctrl+Z。KeyP 确实穿透 capture 层——modal 打开时按 P，面板 pin 状态会在后台切换。修复成本极低（1 行代码追加 `'KeyP'` 到 `suppressKeys`）。

**重分类**: Defer P3 → Patch P3，已应用。

**分类错误根因**: 原审查者未追溯 capture/bubble 事件流，将"遗漏"误判为"有意排除"。

## 认知偏差分析

审查者在 Triage 阶段使用「模式匹配」替代「独立验证」进行分类——对于"看起来像 patch"的发现，使用启发式快速分拣（"代码不一致→patch"、"测试不完整→patch"、"缺少测试→patch"），未对每个候选执行三项校验门禁：

1. **Spec 一致性检查**（导致偏差 #1）
2. **测试职责边界检查**（导致偏差 #2）
3. **测试可实现性检查**（导致偏差 #3）

共识效应加剧了偏差：多个审查层独立标记同一问题被当作"事实可靠 + 分类正确"的证据，而事实上它只证明"事实可靠"。
