## Key Architecture Decisions
- **Negative check ordering**: After `!Number.isFinite(parsed)` guard, before `parsed === this._lastValidRate` no-op check. This ensures negative values are clamped even when previous rate was also 0 (AC4 edge case).
- **Clamp, not reject**: User types -5 → system clamps to 0 + shows warning. Softer UX than hard reject — teaches why negative rates don't apply while still completing the action.
- **Amber (#f9e2af) vs Red (#f38ba8)**: Warning ≠ Error. Error = "cannot parse" (red). Warning = "accepted as 0 but value changed" (amber). Distinct visual semantics.
- **Warning follows existing error pattern**: `_showWarning()` / `_clearWarningTimeout()` mirrors `showError()` / `_clearErrorTimeout()`. Both cleared in `setConnection()` and `destroy()`.
- **No changes to main.ts**: All wiring (onRateSubmit, SNAPSHOT_EMITTED, onConnectionSelect) already exists from Story 4.5/6.2. AC3 (runtime rate editing ≤100ms) already met by existing 10Hz tick interval.
