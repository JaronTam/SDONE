## Audit Corrections Applied
1. **#1 — ControlBar class**: Replaced ad-hoc `updateRunButton()` + inline button handlers with `ControlBar` class (setRunState, onRunPause, onReset callbacks, destroy)
2. **#2 — visibilitychange**: Added `document.addEventListener('visibilitychange')` in `start()`, removed in `pause()`, cleared in `reset()`. Caps time advance at 5s.
3. **#3 — ModalDialog capture-phase**: ModalDialog uses `capture: true` keydown listener to suppress Space/Ctrl+Z/Delete/Tab/Escape while modal is open, preventing bubble-phase handlers from firing
4. **#4 — Reset confirmation modal**: Reset button now opens a confirmation dialog before emitting RESET event
5. **#5 — Status indicator**: ControlBar creates a `<span class="control-bar-status">` element showing IDLE/RUNNING/PAUSED with CSS color coding

## Key Architecture Decisions
- ControlBar follows ModulePanel pattern: constructor(container) → public methods → destroy()
- ModalDialog follows AchievementToast pattern: pure DOM, no EventBus dependency
- ModalDialog keyboard suppression uses capture-phase + stopPropagation (not stopImmediatePropagation) because no other capture-phase listeners exist on window
- visibilitychange handler only advances `engine.t` (not Euler steps) to avoid stock value jumps on tab return
