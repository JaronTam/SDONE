## Key Architecture Decisions
- **AnalyticsPanel follows RateEditorPanel pattern**: constructor(container) → public methods → destroy(), no EventBus dependency
- **`computeStockAnalytics()` is a pure function** co-located in AnalyticsPanel.ts for testability — takes (GraphState, stockId), returns StockAnalytics | null
- **`refreshAnalyticsPanel()` is the single composition-root helper** — all 8 wiring points call this one function (or `analyticsPanel.setStock(null)` directly for clear-only paths), eliminating duplication
- **SNAPSHOT_EMITTED early return fix**: Original handler had `if (!selectedConnId) return;` which would block analytics refresh when no connection is selected. Refactored to `if (selectedConnId) { ... }` so analytics refresh always runs at 10Hz
- **Net change sign convention**: Positive → `+5.0` with green (#a6e3a1), Negative → `−3.0` (U+2212 minus) with red (#f38ba8), Zero → `0.0` neutral
- **NaN guard**: All numeric displays guard against NaN with `Number.isNaN(x) ? '0.0' : x.toFixed(1)`
- **Capacity display**: `Infinity` → "∞", finite → integer via `toFixed(0)`

## Wiring Points (10 integration points in main.ts)
1. **`inputManager.onModuleSelect`** (direct callback, NOT EventBus) — selection changes trigger analytics update/clear
2. **`inputManager.onConnectionSelect`** (direct callback) — selecting a connection deselects modules → clear analytics; null connection click also clears
3. **`inputManager.onModuleDelete`** (direct callback) — deleting a module clears analytics (selection becomes empty)
4. **`inputManager.onConnectionDelete`** (direct callback) — connection deletion changes inflow/outflow → refresh analytics
5. **`inputManager.onTabNext`** (direct callback) — Tab-cycling changes module selection → refresh analytics (AC4)
6. **`rateEditorPanel.onRateSubmit`** (direct callback) — rate change affects inflow/outflow → refresh analytics
7. **`inputManager.onConnectionDragEnd`** (direct callback) — new connection changes inflow/outflow → refresh analytics
8. **`SNAPSHOT_EMITTED`** (EventBus subscription) — 10Hz real-time value updates during simulation
9. **Undo block** (inline keyboard handler) — refresh after state restoration
10. **Redo block** (inline keyboard handler) — refresh after state restoration
11. **`RESET`** (EventBus subscription) — clear to empty state

## Audit-Significant Findings
1. **SNAPSHOT_EMITTED early return bug (caught during implementation)**: The original `if (!selectedConnId) return;` would prevent `refreshAnalyticsPanel()` from executing when no connection was selected. This is the "early return control flow" pattern from Story 6.1 memory (A3). Fixed by restructuring to `if (selectedConnId) { ... }` so analytics refresh always runs.
2. **Direct callback vs EventBus distinction** (from Story 6.1 memory): `inputManager.onModuleSelect` is a direct callback, NOT an EventBus subscription. The `MODULE_SELECTED` event exists in EventMap.ts but is never emitted. This matches the A1/A2 "Spec over Implementation" lesson.
3. **Undo/Redo is inline code** (from Story 6.1 memory): No `.on('UNDO', ...)` subscribers exist — all state mutation happens inline in the keyboard handler. The `UNDO`/`REDO` events are audit-only.
4. **Story spec listed 5 wiring points but 10+ were needed**: The story spec only listed onModuleSelect, SNAPSHOT_EMITTED, undo, redo, and RESET. During implementation, 6 additional paths were discovered: `onConnectionSelect` (selecting a connection deselects modules → clear analytics), `onModuleDelete` (deleting clears selection), `onTabNext` (Tab-cycling changes module selection), `onConnectionDelete` (deleting a connection changes inflow/outflow), `onRateSubmit` (rate change affects inflow/outflow), and `onConnectionDragEnd` (new connection changes inflow/outflow). This reinforces the A1/A2 lesson: always grep the codebase for ALL state-mutation paths that affect the panel's data, not just the ones listed in the spec. The key insight is that analytics panel needs refresh not only on SELECTION changes but also on DATA changes (connection add/delete/rate-change).
